# P0-1 · 原型加随机数种子 + 录黄金录像

先读：`AGENTS.md`、`port/移植计划.md`（§1、§3.2、§3.3）。

## 背景

项目要从原生 JS 原型移植到 Cocos Creator（TypeScript）。移植后的玩法逻辑必须和原型**逐帧一致**，办法是：给原型的随机数加种子，用固定步长、AI 托管玩家跑完整局，定时记录状态快照（"黄金录像"）。以后 TS 版用同样的种子跑，快照必须完全一致。

这是移植期间**唯一一次**改原型代码。玩法、数值、画面、文案一律不改。

## 要做的

### 1. 可设种子的随机数（`js/engine.js`）

- 新增一个可设种子的伪随机数生成器（建议 mulberry32，32 位整数状态），接口：`E.random()` 返回 [0,1)，`E.seed(n)` 重置种子，`E.rngState()` / `E.setRngState(s)` 读写状态（模拟时保存恢复用）。
- 页面正常打开时用 `Date.now()` 之类做初始种子，**玩家体验和现在完全一样**。
- `E.rand`、`E.pick`、`E.shuffle` 改用 `E.random()`。
- `js/game.js`、`js/engine.js` 里所有 `Math.random` 逐个分类：
  - **会被 `update()` 调用链走到的**（不管是玩法还是表现，比如飘字抖动、特效位置），一律改用 `E.random()`。
  - **只在绘制 `draw()` 或纯 DOM / 声音里用的**，可以保留 `Math.random`，但每一处都要在交付报告里列出来，说明为什么它不影响对局状态。
- 不确定归哪类的，改用 `E.random()`。

### 2. 排查其他不确定因素

在 `update()` 调用链里找下面这些，逐项报告（文件:行号 + 结论），**有影响的先停下来报告，不要自己改玩法**：
- `setTimeout` / `setInterval` / `requestAnimationFrame` 回调里改对局状态
- `Date.now` / `performance.now`
- 依赖屏幕尺寸（`st.w`、`st.h`、相机位置）的逻辑判断
- 依赖对象键遍历顺序、`Array.sort` 不稳定性、DOM 读出来的值
- `simulating` 标志导致模拟和真实对局走不同分支的地方（逐个列出）

### 3. `SG_DEBUG.simulate` 支持种子

`SG_DEBUG.simulate(关卡序号, 局数, 种子)`：给了种子就先 `E.seed(种子)`，跑完恢复原来的随机数状态。不给种子行为和现在一样。

### 4. 黄金录像

新建 `tests/golden/`：

- `record.cjs`：用 `tests/game-harness.cjs` 加载真实引擎（必要时给 harness 暴露更多内部函数，只改测试文件，不改游戏逻辑），对每一组（关卡, 种子）：
  - `E.seed(种子)`，玩家交给 AI（同 `simulate` 的 `auto`），不走带教（`makeState(false)`），**固定步长 dt = 1/60 秒**跑到 `S.over`。
  - 每 0.5 秒（第 30、60、90…步）记一份快照，最后结束时再记一份。
  - 快照内容（浮点保留 4 位小数）：对局时间 `S.t`；每个打工人：id、key、x、y、angle、身上每口锅的剩余时间和是否急件、blames、crushed、caught、thrown、misses、parries、piesEaten、当前 AI 目标 id；每个领导：type、x、y、face、state、当前目标；飞行中的锅和甩出去的锅（位置、目标、来源）；地上的饼；日程进度；进行中的事件 / 发火 / 查岗；`S.over`；当前排名（id 顺序）；随机数生成器状态。
  - **事件日志**：整局里每次调用 `E.sfx`、`E.toast`、`showMsg`、`showHint`、`praise`、`floats` 新增飘字、`spawnFx`、`E.buzz`，记下时间和参数（在 harness 里包一层记录，不改游戏代码）。TS 版画面层要靠这个对齐"什么时候该响什么、飘什么字"。
  - 范围：5 关（序号 0–4）× 20 个种子（1001–1020）。
  - 存储：每组完整快照 + 事件日志写 gzip JSON。总体积超过 8MB 的话，种子 1001–1005 存完整，其余只存每份快照的哈希和最终结果，并在报告里说明。
- `verify.cjs`：重新跑一遍，和已存的录像逐项比对，输出第一个不一致的位置（关卡、种子、时间、字段路径、新旧值）。以后 TS 版也接到这个脚本上。
- `README` 不要写；用法写在两个脚本开头的中文注释里。
