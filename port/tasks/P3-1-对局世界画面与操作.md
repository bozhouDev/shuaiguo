# P3-1 · 对局世界画面 + 操作：在 Cocos 里把一局"画出来、能玩"

先读：`AGENTS.md`、`DESIGN.md`、`port/移植计划.md`（§3、§4 的 P3、§6 第 3/5/6 条、§8）、`port/功能清单.md`（§1 主循环、§4、§5、§8、§20、§21）、`implementation-notes.md` 顶部 P2-1 / P2-2 两节、`cocos/assets/scripts/core/` 全部（特别是 `match.ts` 的事件和 `frameAim`）。然后通读原型 `js/engine.js`（输入、Snake 绘制、Floats、精灵加载）、`js/game.js` 的 `draw()` 及它调用的全部 `draw*` 函数、`SPRITES`、`js/atlas.js`。

## 本卡范围（P3 拆成两张）

- **P3-1（本卡）**：对局"世界"——地图、人物、锅、领导、飞行锅、特效、飘字、震屏、相机、屏幕边缘提示；摇杆、甩锅键、键盘；主循环。
- **P3-2（下一张）**：HUD 顶栏、群消息、教学横幅、带教手指、底部提示、下班倒计时浮层。本卡里这些位置先空着，**不要做**。
- 大厅、介绍页、结算等外围界面是 P4，本卡不做。Boot 直接开一局。

## 要做的

### 1. 素材进工程

- 把原型实际加载的像素图搬进 `cocos/assets/resources/`：图集 `assets/atlas/*.png`（14 张）+ 爆炸序列帧 `assets/fx/`。用脚本从 `js/atlas.js` 生成 TS 位置表（`view/atlas-data.ts` 之类），运行时按矩形切 SpriteFrame。脚本放 `cocos/tools/`，能重复运行。
- 所有像素纹理**最近邻采样**，不能糊（P1 的 `player_normal` 做法沿用）。缺图时按原型的后备规则处理（缺走路帧退回 `_normal`，缺爆炸图画放大撞击星）。
- 删掉 P1 冒烟用的 `player_normal.png` 单张（改从图集取），`SmokeView.ts` 删掉。
- 字体：生成**对局里会出现的全部文字**的 TTF 子集（锅名、飘字、人名、领导台词、各关文案……从 `js/levels.js`、`js/game.js` 和 core 里提取，做成脚本）。P1 遗留问题一并解决：`body.ttf` 字重名写的是 Thin，原型用的是思源黑体**粗体**，核对源文件，用对的字重；标题字在编辑器预览里没生效，查清原因修好。
- 新素材加进 `resources` 后编辑器会自动导入生成 `.meta`；导入完成后扫一遍，**任何 `importer: "*"` 都算失败**，要报告。

### 2. 主循环和时间步长（裁定：和原型一致）

- **用原型的做法**：每帧 `dt = min(0.033, 真实帧间隔)` 直接喂给 `match.update(dt)`，然后 `match.frameAim()`，然后画。**不做固定步长**（计划 §3.3 原本的建议作废：core 对任意 dt 都和原型一致，可变步长才能保证手感和原型一模一样，120Hz 手机也不会抖）。
- 暂停、切后台的处理和原型一致（P3 只需保证切后台回来不跳帧）。
- 黄金录像的测试入口不受影响（仍然固定 1/60 跑 core）。

### 3. 画面层结构（`cocos/assets/scripts/view/`）

- 画面层只**读** core 状态 + 消费 core 事件，绝不改 core 状态（`frameAim()` 是唯一例外，是 core 提供的 API）。
- 实现方式你定，但要考虑性能（计划 §6 第 6 条，周四、周五 8 人 + 3 领导是最重的场景）。建议：
  - 地板、墙这类不变的东西一次画进 RenderTexture 或用静态节点，不每帧重画；
  - 人物、锅、领导等用**节点池**（按需取用、多余隐藏），不每帧新建销毁；
  - 扇形、瞄准线、阴影这类几何图形用 `Graphics`，每帧 clear 重画；
  - 文字（锅标签、飘字、倒计时）用 Label 池，注意 Label 改字会重建纹理，数字倒计时类每帧变的要控制频率或换 BMFont 方案，说明你的选择。
- 层级顺序（谁盖谁）、Y 排序、相机跟随、震屏和原型 `draw()` 完全一致。
- 原型 `draw()` 里用 `E.fxRand` / `Math.random` 的表现随机，画面层用自己的表现随机，**绝不能调用 core 的随机数**（会改变玩法）。

### 4. 要画出来的东西

按 `port/功能清单.md` §4、§8、§20 和 §21 里属于"世界"的每一项实现，每项做完在报告里打勾或写明没做的原因。重点别丢：走路帧动画节奏、躺平 / 被压垮、表情和冒汗（阈值以代码为准 ≥8 口，见计划 §9 第 2 条）、锅的倒计时标签和急件样式、尾巴、飞行锅旋转、天降阴影、爆炸跟着人走、领导视野扇形（发火、查岗状态）、瞄准扇形四种颜色（红 / 绿 / 白 / 灰）和套住目标、屏幕边缘的人物 / 锅提示、画饼、小舅子、老板娘、出纳等各关特有表现、飘字（颜色、上飘速度、寿命）、震屏强度。

### 5. 操作

- 摇杆（画面任意位置按下都算、底座位置半径、死区、幅度）、甩锅键（含锅飞来时变"弹"的状态、冷却灰态）、网页版键盘（方向键 / WASD / 空格）。数值全部照 `js/engine.js` 输入部分和功能清单 §5。
- 输入写进 core 的 `inp` 对象，写法与原型 `pollKeys` 等逐项对应。
- 多点触控：一只手摇杆、一只手按甩，要同时生效（原型是怎么处理的就怎么处理）。

### 6. 调试入口（编辑器预览用）

预览地址支持 URL 参数：`level`（0–4）、`seed`、`auto=1`（玩家交给 AI）、`freeze=步数`（用固定 1/60 跑到第 N 步后停住，只画不更新，用于截图对比）。正式包里这些参数无效（只在 `kind === 'web'` 且带参数时生效）。

### 7. 截图对比（验收主手段）

- 原型：本地 `python3 -m http.server` 起原型，用 Playwright 打开，**通过注入脚本**（不改原型文件）做到：指定关卡、种子、auto，用固定 1/60 跑到第 N 步后停住画一帧。
- Cocos：编辑器预览 `http://localhost:7456/?scene=3b08c73f-d17c-4dfc-a45e-854ddae97b2f&level=..&seed=..&auto=1&freeze=N`，同样 375×812（沿用 P1 的移动端浏览器上下文做法）。
- 每组拼成左右并排一张图存 `port/tmp/p3-1/`。范围：5 关 × 3 个时刻（开局 2 秒、中段、快结束），种子 1001；再加你认为最能暴露差异的场景（领导发火、爆炸瞬间、瞄准套住目标、画饼会议、小舅子），至少 6 张。表现随机（震屏偏移等）造成的细微差别可以忽略，其他差异要么修好，要么在报告里逐条列出原因。
- 用完关掉原型服务，确认端口没在监听。

### 8. 性能

- 在编辑器预览里跑周五 auto 一整局，记录帧时间（平均、最差 1%），和原型在同一浏览器里对比。
- 列出最耗时的几项，以及你做了什么优化。真机满帧由泊舟用手机验收。
