# P2-2 · 补齐黄金录像没覆盖的逻辑：手动操作、带教、增益、结算、模拟统计

先读：`AGENTS.md`、`port/移植计划.md`（§4 P2、P3 的"硬性要求"）、`port/tasks/P2-1-玩法逻辑翻译.md`、`implementation-notes.md` 顶部 P2-1 一节、`tests/golden/record.cjs`、`tests/golden/verify.cjs`、`cocos/tests/golden-adapter.cjs`、`cocos/assets/scripts/core/` 全部。

## 背景

P2-1 的 100 组黄金录像只覆盖"玩家由 AI 托管、无带教、无增益、跑到 `S.over` 为止"。下面这些还没有被逐帧验证，本卡把它们补上。方法和 P0 / P2-1 一样：**在原型上录，TS 版必须完全一致**。原型代码仍然不许改（只能改测试和 harness）。

## 要做的

### 1. 手动输入录像（覆盖玩家操作路径 + 画面层瞄准要求）

- 原型里玩家不托管（`auto = false`）时，靠输入对象（摇杆方向、力度、甩锅键按下）驱动。写一个**确定性的输入脚本生成器**：用独立种子生成每帧的摇杆角度 / 力度（包括 `TURN_ONLY_MAG` 以下的轻推、松手、急转）和甩锅按键（包括锅飞来时按"弹"、空按触发 `WHIFF_LOCK`、冷却中连按），要有足够多的甩锅和反甩发生。
- **每帧顺序**：`update(dt)` 之后调用一次 `pickAim(P)`，模拟原型 `draw()` 里的那次调用（见计划 P3 硬性要求）。录像和 TS 版都按这个顺序。TS core 要提供一个明确的 API（比如 `match.frameAim()`）给以后的画面层用，注释写清楚为什么必须每帧调。
- 另录一组**不调用** `pickAim` 的对照，证明这次调用确实影响状态（如果完全不影响，在报告里说明，那条硬性要求可以撤销）。
- 范围：5 关 × 10 个输入种子。存到 `tests/golden/input/`，`verify` 能比对（可以给 `record.cjs` / `verify.cjs` 加模式参数，**已有 100 组录像的比对逻辑不许改**，改完那 100 组照样 PASS）。

### 2. 带教录像

- 周一带教（`makeState(true)`）：用脚本化输入按教练提示完成全部 7 步并正式开局，录到 `S.over`。带教里需要玩家做的动作（走到某处、按甩、躲开、点"开始上班"等）在原型里怎么判定，就按什么写脚本。另录一组"跳过教学"按钮的路径。
- TS 版逐帧一致。

### 3. 增益录像

- `BUFFS` 的 4 种增益（`trip`、`gold`、`news`、`legs`）各在 5 关上跑 3 个种子（托管玩家即可），`makeState(false, buff)`。逐帧一致。

### 4. 结算与广告

- 把原型 `finish()` 里的纯计算（名次、星级、总账、复盘推荐 `diagnose`、成就、彩蛋/证书判断、存档写入内容）和 TS core 的对应函数对比：对所有黄金录像的终局状态，以及第 1–3 节的终局状态，结算结果完全一致。
- 存档：原型写 `localStorage` 的内容（`shuaiguo_v3` 的 `unlocked`、`best`、`stars`、成就等）和 TS 返回给平台层的存档内容完全一致，包括"旧存档按背锅次数比、新存档按总账比"的兼容分支（构造旧存档测）。
- 广告复活（压垮后甩掉 6 口接着熬）、顶包（减 3 后重新结算）：在原型里触发对应的处理（跳过 `E.fakeAd` 的等待，直接调回调），对比之后继续跑到结束的整局录像和重新结算结果。
- 收尾：`startClosing` / `updateClosing` 里属于逻辑的部分（下班倒计时期间状态冻结、到点判定）一致。

### 5. 模拟统计

- 把 `SG_DEBUG.simulate` 搬到 core（比如 `core/simulate.ts`），同一个种子下，原型和 TS 版 5 关各 50 局的统计结果**完全相同**（是逐字段相同，不是"差不多"）。写成测试。

### 6. 搬测试

- `tests/thursday.cjs`、`tests/friday.cjs`、`tests/random.cjs` 的每一条断言，在 TS core 上各写一份等价测试（`cocos/tests/`），全部通过。断言不许放宽；原型测试里用 `Math.random = () => 0.5` 之类的替身，TS 里用对应方式实现。

## 验收门槛

1. 原 100 组：原型 `verify` 和 TS `verify --adapter` 都 100/100。
2. 新增的手动输入、带教、增益录像：原型自己重跑一致，TS 版全部一致。
3. 结算 / 存档 / 广告 / 收尾对比全部一致。
4. 模拟统计逐字段相同。
5. 搬过来的测试全过；`npm run test:core`、`check:types` 通过。
6. 原型 `js/`、`index.html`、`css/`、`assets/` 哈希不变；原有 100 组录像文件不变。

不一致只能通过把 TS 改对来解决。确信是原型本身的问题（比如依赖了 DOM 时序），停下来报告证据。

## 不许做的

- 不改原型代码；不改原有 100 组录像。
- 不碰 `view/`、`platform/`、场景和素材；**不许运行 CocosCreator**。
- 不顺手改好任何东西（发现的问题列进"发现但未改"）。
- 不提交、不推送、不部署。

6. 验收：删掉本地全部新录像 → `verify-extra.cjs --adapter cocos/tests/extra-adapter.cjs` 能自动重建并 PASS 177/177；原 100 组两边都 100/100；`npm run test:core` 通过；`git status` 里看不到新录像文件。
