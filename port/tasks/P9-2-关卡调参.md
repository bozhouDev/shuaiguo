## 要做的

1. **工具**：把 `port/tmp/p9-2/sim-detail-orig.mjs` 搬成正式工具 `cocos/tools/sim-detail.mjs`：路径改成相对路径；参数支持局数、关卡列表、种子、`--items`（开道具）；输出 §4.4 第 3 条要的全部列，另加机读 JSON（`--json`）。中文注释。用法写在文件开头。
2. **调参**：严格按 §4.4 的流程：
   - 顺序：周三 → 周二、周四 → 周五 → 最后看周一。
   - 旋钮优先级：第一档 `aiEnd.aggr`、`aiEnd.focus`、`leaderFocus`；第一档调到头还不够，才动第二档 `pace`、散会口数；最后才是 `potLife`、`startPots`。每升一档，在报告里写清楚理由：第一档为什么不够，要有数据。
   - 每轮只改同一类旋钮，每轮都记录一行（关卡、改了什么、6 列结果）。
   - 曲线约束保持 §4.1 的「曲线」列：单调的要保持单调，锯齿（新角色关开局比上一关下班时低）要保留，`aiEnd.parry` ≤ 1.2。
   - **不许动**：时长、同事 / 领导编成、`skyChance`、`SKY_GAP`、`PARRY_MAX`、`CLEARING`、事件时间点、`config.ts` 里任何全局常量、AI 代码本身。只改 `levels.ts` 的关卡数据。
3. **防过拟合**：调参用种子 6011 跑 100 局；定稿后再用种子 7013 跑 **300 局**复核。复核结果每格允许比目标区间宽 5 个百分点（例如周三通过率 35–55%）；复核不过的那一关要接着调。另外把定稿后 `--items` 开道具的结果也列出来，只记录、不作为目标。
4. **调不到怎么办**：某一关调了 15 轮还达不到，或者三个目标互相冲突（比如压垮降下来了，差一点占比却上不去），**停下来**，把最接近的两三组方案和各自的数据列进报告，交给泊舟定。不许为了达标去改上面「不许动」的东西。
5. **重录**：定稿后跑 `npm run golden:record`、`npm run golden:record:extra` 重录，再跑 `npm run cloud:prepare` 同步云函数副本。录像只能因为数值变化而变化，不能有别的原因。
6. **介绍页和带教**：如果某关的关卡介绍、`tips` 文案里写了具体数值（例如「锅 24 秒到点」），要和新数值保持一致；改了文案就跑 `npm run fonts:subset`。

## 第二轮（Claude 2026-11-05 审查第一轮后的裁定，**以本节为准**，和上文冲突的地方按本节）

第一轮报告：`port/tmp/p9-2/report.md`。第一轮严格按卡执行、按停止规则停下，做法没问题。卡本身有两处缺陷，导致调不出来，现修正如下：

### 裁定 1：样本量

100 局下「排名失败」只有十几局，差一点占比的噪声在 ±10 个百分点以上。Claude 用正式工具复测了开工基线（300 局）：

| 关 | 种子 6011 通过 / 压垮 / 差≤2 | 种子 7013 通过 / 压垮 / 差≤2 |
|---|---|---|
| 周一 | 79.0 / 0.3 / 62.9 | 74.0 / 0 / 66.7 |
| 周二 | 86.3 / 2.7 / 39.4 | 84.7 / 1.3 / 52.4 |
| 周三 | 29.7 / 20.3 / 22.7 | 32.7 / 17.0 / 19.9 |
| 周四 | 16.7 / 34.3 / 19.0 | 23.0 / 28.0 / 17.0 |
| 周五 | 5.3 / 37.7 / 7.6 | 5.7 / 36.7 / 9.8 |

第一轮里周二的 79% 是 100 局下的运气，实际是 85% 左右，**偏简单**；周一 74–79%，**偏难**。所以改成：

- **每轮评估** = 种子 6011 和 7013 各跑 300 局，**合并成 600 局**判断是否达标（达标用的是严格的 §4.3 区间）。
- **复核** = 定稿后用种子 8017 跑 300 局，每格允许比目标区间宽 5 个百分点。
- 工具里加一个多种子合并的选项，例如 `--seeds 6011,7013`。

### 裁定 2：曲线约束的口径

§4.1 把 `aiEnd.focus`、`leaderFocus` 标成「单调」，但现值是周二 1.3 → 周三 1.2、周二 .30 → 周三 .25，这和同一张表里「新角色关开局比上一关下班时低」的锯齿是同一个意图。统一口径如下：

- **周三是新角色关（加经理、加同事、加小舅子），允许 `aiEnd.focus`、`leaderFocus`、`aiEnd.aggr`、`pace` 比周二低或松**；周三之后（周三 → 周四 → 周五）必须非递减（pace 间隔非递增）。
- 周一 → 周二也必须非递减（周一没有 `leaderFocus`，按 0 算）。
- `aiEnd.parry` ≤ 1.2，`bursts` 和 `events.n` 保持现值，其余「不许动」清单不变。

### 轮数和顺序

- 顺序不变：周三 → 周二、周四 → 周五 → 周一。周一要降难度（目标 85–95%），按同样的旋钮优先级调。
- 每关最多 **25 轮**（第一轮已经跑过的周三 8 轮、周二 15 轮不计入，因为口径变了）。从第一轮的候选出发也可以，但要先用 600 局重测。
- 旋钮优先级和「升档要写理由」不变。周三到周五主要是压垮太多（同事每局砸 19 到 29 口），第一档调到头还不够时，第二档、第三档（`potLife`、`startPots`）按规则可以用，这是预期内的，不要因为升档而犹豫。
- 停止规则不变：25 轮还不达标，或者目标互相冲突，就停下来，列出候选方案交给泊舟定。
