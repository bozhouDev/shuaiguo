先读：`AGENTS.md`、`port/移植计划.md`、`port/功能清单.md`、`implementation-notes.md` 顶部（P4-1 之后全部）、`tests/golden/`、`cocos/tests/golden-adapter.cjs`、`cocos/tools/check-spread.cjs`、`cocos/assets/scripts/` 全部。

## 背景（今天在微信里踩到的坑）

- 网页预览一直是对的，但微信包出了两次错：`URLSearchParams` 不存在导致启动就崩；Cocos 打微信包时 Babel 用宽松模式，把 `[...字符串]` 编成 `[].concat(字符串)`，所有文字宽度只算一个字，排版全部错位。
- 也就是说：**黄金录像 100/100 只证明了 TS 源码在 Node 里对，不证明微信里跑的编译产物对。**泊舟要求先确认微信版的玩法和画面都已还原，再做别的。
- 泊舟会按需在编辑器里刷新、构建。现在的构建在 `cocos/build/wechatgame-001/`（已包含今天所有修复）。微信开发者工具开着这个项目，改了构建目录里的文件会自动重新编译。

## 要做的

### 1. 编译产物上跑黄金录像

写 `cocos/tools/golden-compiled.cjs`：从 `cocos/build/wechatgame-001/assets/main/index.js`（SystemJS `System.register` 打包）里取出 core 各模块，在 Node 里用一个最小的 System.register 加载器跑起来（core 不依赖 `cc`；如果打包里 core 和画面层混在一起，只加载 core 需要的模块，`cc` 给空桩），然后用和 `golden-adapter.cjs` 完全相同的快照 / 事件 / 结果规则，跑原始 100 组黄金录像。

- 输出 `PASS 100/100` 或第一处不一致（关卡、种子、帧号、字段）。
- 先做一次变异验证：临时改编译产物里的一个数值，确认它会报错，再改回来。
- `cocos/package.json` 加 `test:golden:compiled`。
- 如果不是 100/100，**这是最高优先级**：找出源码里哪种写法被宽松模式编坏了，修源码，并把这类写法加进 `check-spread.cjs` 或 `tests/wechat/globals.test.mjs` 的禁用检查。修完以后要等泊舟重新构建才能复验，在报告最前面写清楚。

另外检查编译产物里有没有别的宽松模式和小游戏环境的隐患：`for...of` 遍历 Map / Set / 字符串、`Array.from` 带映射函数、`class` 字段、getter / setter、`Symbol.iterator`、正则 `u` / `s` 标志和 `\p{...}`、可选链、`??`，以及微信开发者工具自己的"ES6 转 ES5"二次编译（今天它对手改的产物报过 `returnArray is not defined`）。逐项给出结论（安全 / 有问题 / 无法确定 + 理由）。

### 2. 微信开发者工具巡检模式

需要一种不碰鼠标、不需要人操作，就能在微信开发者工具里把各个画面依次放出来截图的办法。

- `AppView` 读 `globalThis.__SG_TOUR`（只在 `debugEnabled()` 为真时，也就是网页 `?debug=1`、微信开发版 / 体验版；正式版完全不可达）。值是一个步骤列表或预设名 `'all'`。
- 预设 `all` 依次展示：大厅、选中第 5 关的大厅、玩法弹窗、改老板名、5 关介绍页、对局（周一带教第 1 步和第 3 步、周三 auto 跑 60 秒定格、周五 auto 跑 150 秒定格）、暂停、设置、结算（过关 3 星、1 星、没过关、压垮、周五证书）、复活后、分享预览、表扬贴纸、好友排行页。种子固定，和 `port/tmp/p4-1/` 里原型截图用的条件一致，方便对比。
- 每到一步，打一行 `console.log('[SG TOUR]', 序号, 名字)`，停 `hold` 秒（默认 4 秒），然后自动进入下一步；全部放完打印 `[SG TOUR] done`。
- 触发方法：在 `cocos/build/wechatgame-001/game.js` 第一行加 `globalThis.__SG_TOUR='all';`，开发者工具会自动重新编译。**只能改 `game.js`**，不要改 `assets/main/index.js`（开发者工具二次编译手改的产物会出错）。
- 截图：用 `screencapture -x -o -l <窗口号> 文件.png` 直接截开发者工具窗口（窗口被挡住也能截）。窗口号的查法：用 swift 调 `CGWindowListCopyWindowInfo`，找 owner 是"微信开发者工具"、标题含 `shuaiguo-cocos` 的那个窗口；窗口号会变，每次重新查。按日志的步骤时间截图，把模拟器区域裁出来。
- 巡检模式本身写成纯逻辑（步骤表、计时）加 Node 测试；网页 `?debug=1` 下也要能跑，你可以先用 7456 网页预览验证流程。
