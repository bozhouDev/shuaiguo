## 目标

原型里盖在画布上的 DOM 界面（对局中的部分），在 Cocos 里用节点重建，**外观、文案、出现时机、动画时长和原型一致**。做完这张卡，一局从开场（含周一带教）到 18:00 收尾，除了结算界面以外都完整。

## 范围

- **HUD 顶栏**（功能清单 §6 全部）：时钟、锅数和进度条、名次、背锅、增益标签、连甩、右侧按钮（跳过教学、设置、暂停）、带教时的隐藏与闪烁、变红规则、窄屏和折行、等宽数字。
- **群消息、教学横幅、带教、底部提示**（§7 全部）：包括带教手指、"开始上班"按钮、跳过教学流程。
- **下班倒计时与收尾**（§9 全部）：倒计时浮层、收尾阶段按钮置灰、到点后的过渡，到"该弹结算"为止。
- toast（`E.toast`）。
- 暂停和设置按钮**点下去**以后要打开的面板是 P4，本卡里点暂停只需让对局真正暂停 / 继续（用一个最简单的占位面板，P4 替换），设置按钮先只打日志。
- 结算界面是 P4。本卡在 `S.over` 后显示一个占位卡片（名次 + "结算界面 P4"），点一下回到新的一局，便于连续测试。

## 要求

### 1. 实现方式

- 全部节点在代码里创建（计划 §3.4），放在 `view/` 下独立文件（如 `HudView.ts`、`MessageView.ts`、`TutorialView.ts`、`ClosingView.ts`），由 `WorldView` 或 Boot 组织。
- CSS 的样式（深蓝面板、暖白字、2px 内高光、硬投影、切角框、红底）用 Sprite 九宫格 / Graphics 还原。需要 9-slice 底图的话，用脚本生成像素风 PNG 放 `resources/ui/`，不手画、不用外部素材。像素 UI 图标沿用图集里的 `ui_*`。
- 文字字体、字重、字号照原型 CSS（P3-1 已准备快乐体 400、思源黑体 700 / 900）。本卡新出现的文字（HUD、群消息、带教台词、按钮）要加进字体子集，**重新跑字体裁剪脚本**，确认没有字退回系统字体。
- 时长分两种（功能清单开头写明）：对局秒（暂停会停）和真实时间（暂停不停）。每个计时器在代码注释里写清是哪一种，和原型一致。
- 文字频繁变化的（时钟、背锅数）控制重建频率：只有显示内容变了才改 Label。

### 2. 顶部安全区（为微信胶囊预留）

- HUD 和群消息等所有贴顶元素的位置，统一通过平台层给的一个 **顶部避让区**（比如 `platform.topInset()` / 胶囊矩形）计算。网页实现返回 0，布局和原型完全一致。
- 微信实现本卡只写接口和注释，真实避让在 P5 做。但布局代码要保证：顶部下移、右上角让出一块矩形时，HUD 能自动折行或下移而不重叠。用假数据（顶部 44px、右上 87×32 的胶囊）截一张图证明。

### 3. 带教

- 周一首次（空存档）进入走带教，`?tut=1` 强制带教。7 步每一步的台词、手指位置与动画、要求玩家做的动作、放大闪烁的 HUD 块，和原型一致。
- "跳过教学""开始上班"两个按钮的流程和原型一致。
- 带教相关的状态推进都在 core（P2 已验证），画面层只显示、只把按钮点击传回 core。
