# P7-4 · 卡顿第二轮：对局里每帧少画点

先读：`port/tasks/P7-3-第5关卡顿.md`、`port/tmp/p7-3/report.md`（第一轮测量口径、基准工具、像素对比方法都沿用）、`implementation-notes.md` 顶部、`cocos/assets/scripts/view/DrawSurface.ts`、`WorldPainter.ts`、`WorldView.ts`、`MatchUi.ts`、`HudView.ts`、`PerfProbe.ts`、`cocos/tools/perf-bench.mjs`。

## 背景

- 第一轮（fff84ef）解决了"进对局卡一下"，对局中每帧的开销基本没降：第 5 关每帧约 150 次 draw call、35 个 Graphics 每帧 clear 后重新三角化、50 个 Label。
- 泊舟真机反馈（iPhone 17 Pro、小米 17 Pro）：**越到后面越卡**（场上锅越来越多），一局下来手机发烫；卡顿时偶尔"卡一会会"。还反馈"好像突然变大了一点点"，具体什么时候、什么东西变大还在问，**你先查一下有没有任何会改变画面缩放或视口大小的路径**（canvas-resize、安全区 / 胶囊回调、DPR 变化、帧率切换前后的视口、震屏、`frameRate` 切 15/60 时引擎是否重设画布），列出来并说明哪种可能对上"突然变大"，不要改，等 Claude 确认。
- 两台旗舰都卡、都发烫，所以问题很可能在 GPU 填充率或 draw call / 每帧重建网格，而不只是 JS。

## 要做的（按收益从大到小，每项单独测）

1. **渲染分辨率**：现在大概按设备满分辨率（DPR 3）渲染。像素风素材本来就是放大的，评估把渲染分辨率封顶到 DPR 2（或按设计宽度的整数倍），比较清晰度差异（给 DPR 3 / 2 的截图对比）。这项对发热收益可能最大。要保证触摸坐标、文字清晰度、像素图不糊（最近邻采样）。
2. **长局后期的开销**：用固定种子 auto 跑第 5 关到 150 秒、170 秒（锅最多的时候），量每帧指标，找出随锅数增长的部分（锅本身、倒计时圈、头顶提示、边缘箭头、爆炸粒子、飘字等）。
3. **减少 draw call**：
   - 同一张图集的 Sprite 尽量连续提交；Graphics、Label 夹在中间会打断合批。看能不能按层整理绘制顺序，而不改变遮挡关系（视觉上谁压谁必须和原型一致）。
   - Label 用 `CacheMode.CHAR`（共享字符图集），让文字也能合批；验证中文字和描边效果不变。
4. **少重建几何**：人物影子、视野扇形、倒计时圈这类每帧重新三角化的 Graphics，形状不变时只改节点位置、旋转、透明度；必须变形状的（倒计时圈进度）考虑用预先画好的 Sprite + `FILLED` 径向填充代替 Graphics。
5. 每项都要给出第 1 关、第 5 关（开局 10 秒和 150 秒后）的前后对比。没有测出收益的改动不要保留。

## 不能破坏的

- 玩法一帧不变：黄金录像（源码 + `test:golden:compiled`）100/100。
- 画面：第 1 / 3 / 5 关固定种子定格截图逐像素比（方法同第一轮），并加一张第 5 关 150 秒后的定格。分辨率封顶那一项会有预期差异，单独出对比图，说明差在哪。
- 门槛同前：core、wechat、cloud、check:types、保护检查、`.meta`、check-spread、perf / tour / result-view 测试全过。

## 不许做的

- 不运行 CocosCreator，不构建，不提交，不推送。不改原型，不改玩法和数值。
- 不改结算弹窗的设计。
