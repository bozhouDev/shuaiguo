## 要做的（`WechatPlatform` 及相关画面层接入点）

1. **存档**：`wx.getStorageSync / setStorageSync`，键名和 JSON 格式与网页版完全一致；异常时按原型规则降级（读失败当空存档，写失败静默）。
2. **激励视频广告**（复活、顶包、广告增益）：
   - 广告位 ID 放一个配置文件（比如 `platform/ad-config.ts`），现在为空。为空、创建失败、拉取失败、`onError`、用户中途关闭，都返回"没有奖励"，界面走 P4-1 已做的降级（保留结算，不发奖励）。
   - 每种用途一个实例还是共用一个，按微信推荐做法定，说明理由；处理好 `load → show → onClose(isEnded)` 和重复点击、对局已切走等时序。
   - 广告播放期间暂停 BGM，关闭后恢复。
3. **分享**：
   - `wx.showShareMenu`（好友 + 朋友圈）、`wx.onShareAppMessage`、`wx.onShareTimeline` 设置默认分享内容。
   - 结算页"分享"调用 `wx.shareAppMessage`，标题 / 图片按原型分享卡的文案和画面：图片用 Cocos 渲染分享卡到 RenderTexture 再导出临时文件（`canvas.toTempFilePathSync` 或等价做法），失败退回默认图。标题文案不包含玩家自定义的老板名（避免内容安全问题，见计划 §5）；如果原型分享文案里有，报告里列出并给建议，不擅自删。
4. **震动**：毫秒数映射到 `wx.vibrateShort({ type })` / `wx.vibrateLong`，映射表写清楚理由（短于 ~50ms 用 light 等）；设置关时不震。
5. **顶部避让 / 安全区**：`wx.getMenuButtonBoundingClientRect` + `wx.getWindowInfo().safeArea` 换算到设计分辨率（375 宽 FIXED_WIDTH），实现 P3-2 定义的顶部避让接口。获取失败时用保守默认值。
6. **生命周期**：`wx.onHide` 自动暂停对局（和网页切后台一致）、`wx.onShow` 恢复 BGM（对局保持暂停，等玩家点继续——按原型网页切后台的做法定）；埋点在 onHide 时上传（P6-1 已有队列，接上即可）。
7. **音频**：
   - 微信端用 `wx.createInnerAudioContext` 或 Cocos AudioSource，按能满足需求的来：P4-1 报告里"连甩音高递增"需要变速（`playbackRate`），Cocos AudioSource 做不到就用 InnerAudioContext 做音效。同时注意微信同时播放的实例数上限，做一个小的实例池。
   - `obeyMuteSwitch`（iOS 静音键）：音效跟随静音键、BGM 也跟随（和大多数小游戏一致），写成一处常量方便改。
   - `wx.onAudioInterruptionBegin / End`（来电等）：暂停 / 恢复 BGM。
8. **分包加载**：音频 bundle、resources bundle 已是小游戏分包。启动时显示加载进度（P4-1 的加载浮层），用 `assetManager.loadBundle` / `wx.loadSubpackage` 的进度回调；某个分包加载失败时重试一次，再失败给出可点击重试的提示，不白屏。
9. **改老板名输入**：确认 Cocos EditBox 在微信端会调起 `wx.showKeyboard`；如果有已知坑（确认键、长度限制、中文输入），在代码里处理并在报告写清楚明天要真机看什么。
10. **调试门禁**：P4-2 E 项的 `envVersion` 判断接上真实的 `wx.getAccountInfoSync()`。
