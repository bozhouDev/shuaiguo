### 2. 数据库设计

集合（名字可调，报告里说明）：
- `saves`：云存档，`_id = openid`。
- `events`：埋点。
- `ranks`：全服排行，每人每关一条最好成绩。
- `config`：远程调参，一份当前生效的配置文档。

**权限**：所有集合客户端不可直接读写，一律经云函数。用云函数在首次调用时 `createCollection`（已存在则忽略），并在报告里写清楚泊舟需要在控制台手动确认的权限设置（如果命令行改不了）。给 `ranks`、`events` 设计必要的索引，写清楚要不要手动建。

### 3. 云函数

每个函数：参数校验、错误返回统一结构 `{ ok, data?, error? }`、不信任客户端传来的 openid（用 `cloud.getWXContext().OPENID`）。

1. **`config`**：返回远程调参配置 + 版本号。
2. **`save`**：`get` / `put`。合并规则（不是简单覆盖）：每关 `best` 按原型的比较规则取更好的（有总账比总账、旧存档按背锅次数，和 core 一致，复用同一套比较逻辑并测试）；`unlocked` 取大；`tutDone`、`achievements.*` 取或；`bossName` 取最近修改的那份（存档里加 `bossNameAt` 时间戳，本地存档也要加，兼容没有这个字段的旧存档）。返回合并后的结果，客户端以它为准写回本地。
3. **`track`**：批量写埋点。单次最多 N 条、字段白名单、单个用户频率限制（防刷），超限丢弃不报错。
4. **`rank`**：`submit`（每关最好成绩，合理性校验：总账、名次、对局时长、星数在关卡允许的范围内，范围从关卡数据推导；不合理拒收）、`top`（某关前 50 + 我的名次）。显示名先用匿名的"打工人#后四位"（不上传老板名等自定义文字，避免内容安全审核，见计划 §5 注意事项）。

### 4. 客户端接入层（`platform/`）

- 在平台接口上加云能力：`cloud.init()`、`cloud.call(name, data, timeoutMs)`。网页实现全部返回"不可用"；微信实现用 `wx.cloud.init({ env })` + `wx.cloud.callFunction`，**每次调用都带超时**（建议 3 秒），超时 / 失败返回"不可用"，绝不抛到游戏逻辑。
- **远程调参**：
  - 启动时异步拉取，**不阻塞进大厅**；拿到后缓存到本地，下次启动先用缓存。
  - 只允许覆盖白名单内的数值字段（关卡时长、锅期限、各种倍率等，从 `levels.ts` / `config.ts` 挑真正适合线上调的），每个字段有上下限，超出就忽略该字段。
  - 只在**开新一局时**生效，对局中途不变。
  - 配置为空时游戏和现在完全一样：黄金录像必须仍 100/100。
  - core 需要能接受"本局用的关卡参数"（如果现在是直接读常量，加一个最小改动的注入口，默认值不变）。
- **云存档**：启动时拉一次与本地合并；每局结算、改老板名、看完带教后上传（防抖）。断网时只用本地，联网后下次再同步。
- **埋点**：本地排队，结算 / 切后台 / 队列满时批量上传，失败留在队列下次再发，队列有上限。事件：开局（关卡、增益、是否带教）、结算（名次、星、总账、背锅、是否压垮及时刻、复活 / 顶包、时长）、带教每步、广告展示 / 结果、分享。调试模拟（simulate）不埋点。
- **全服排行**：结算有星时提交；读取接口给以后的界面用。
- **好友排行（主域部分）**：结算有星时 `wx.setUserCloudStorage` 写每关最好总账（KVData 格式自行设计并写清楚，给明天做开放数据域用）。
