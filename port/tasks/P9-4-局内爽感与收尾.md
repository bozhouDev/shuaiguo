## 已定的裁定（需求文档没写清的地方，按这里做）

1. **慢动作只做在画面层**：core 只发事件（例如 `E.event('ownedBoom', …)`、`E.event('buzzer', …)`），`WorldView` 收到后在接下来的**真实时间** 0.2 秒（压哨 0.6 秒）内把喂给 `m.update()` 的 dt 乘以 0.15（压哨 0.2）。core 不加任何「时间倍率」状态，模拟和录像完全不受影响。两段慢动作重叠时取更慢的那个，结束时间取更晚的那个；同一帧多口锅炸，只触发一次。
2. **`Pot.lastThrower`**：每次甩出（含反甩弹回）时写入甩的人；领导、散会、天降、撞领导、急件来的锅为 `null`。快照里按 agent `id` 存，不能把 Agent 对象整个塞进去。
3. **名次变化检测放 core**：每帧更新后比较玩家实时名次和上一帧，变化时发事件 `{ from, to, who }`，`who` 按需求 §7.2「正下方 / 正上方」规则取；只有「升名次」和「掉出线」才发喊话事件。周一带教阶段、玩家被压垮后不发。画面层负责横幅 0.8 秒和替换不叠加，不占 `tips` 的名额。
4. **压哨下班**：core 在清账起点记下 `S.clearingRank`（玩家当时名次）；铃响判定 `clearingRank > passRank` 且最终名次 ≤ `passRank` 时，`calculateResult()` 里给出 `buzzer: { from, to }`，同时发 `buzzer` 事件。画面层在铃响后、结算页出来前放 0.6 秒慢动作和横幅「{时钟} 压哨下班」；结算页战报首句固定为「最后 15 秒从第 {from} 翻到第 {to}」；证书上加文字印章「压哨」（`ui_stamp_buzzer` 没出图，先用文字，颜色按 DESIGN §3 选绿或黄，报告里说明）。
5. **被甩中台词（§7.4）**：按 `ROLES` 的 key 配（会计 `pm`、新来的 `intern`、老油条 `veteran`、业务员 `tester`、美工 `designer`、出纳 `cashier`，小舅子按现有 key），每人 3 句按顺序轮换，不随机（不消耗 `E.random`，录像不变）。「10 秒内第 3 次」按真实对局秒数计。台词数据放 core 或 view 的数据文件都行，但只能由「玩家甩中」触发，同事甩中同事不说话。
6. **报仇标记（§7.5）**：core 给每个同事记 `grudgeUntil`（同事甩中玩家时 = `S.t + 5`），玩家甩中他且 `S.t < grudgeUntil` 时发「礼尚往来」事件，记一局次数，第 3 次发「冤冤相报」。标记、飘字、横幅都在画面层画。
7. **战报三行（§7.6）**：`player.kills: Record<string, number>`（按同事名计，「`lastThrower` 是你且在他身上到点」）、「害你最多」从 P9-3 的 `blameLog` 按 `src == mate`（`bell` 取 `orig`）统计、「最险一口」= 玩家每次甩出并砸中时的 `due − S.t` 的最小值（保留一位小数，≥ 3 秒不显示）。三行的文字由 P9-3 的文案纯函数模块输出，画面层只摆放；并列时取最早达到这个数的人。
8. **玩家被同事的锅炸**：飘字改成「背锅 +1 · {同事名}甩的」，判定用 `Pot.lastThrower`（是同事才改）。急件仍是 `+3`。
9. **音效**：「嘿嘿」没有素材，用现有 `praise`；「礼尚往来」用现有 `parry`。不新增音频文件。
10. 画面全部沿用 P7-6 的常驻节点画法，不退回每帧重画；新加的飘字 / 头顶标记要进 retained 测试，perf 测试不能变差（报告里给第 5 关改前改后的 draw call 数）。

拿不准的其他细节：选最保守的做法，写进报告「待裁定」。

## 测试（node:test，放 `cocos/tests/`）

- `lastThrower` 流转：甩出写入、反甩弹回改成弹回的人、领导 / 天降 / 散会来的锅为 `null`、同事甩给同事再到点不触发「你甩的」。
- 我甩的锅炸在同事身上发事件；同一帧两口只发一次定格。
- 名次事件：升名次点名正下方的人；掉出线点名正上方的人；线内掉名次不发；带教阶段不发。
- 压哨：清账起点在线外、铃响在线内 → `buzzer` 有值，战报首句正确；反过来没有。
- 台词按顺序轮换，10 秒内第 3 次换成「你是不是针对我」；同事甩同事不说话；台词不消耗随机数（同种子录像剔字段后不变就是证明）。
- 报仇：5 秒内回甩发「礼尚往来」，第 3 次发「冤冤相报」，超过 5 秒不发。
- 战报三行各有数据 / 无数据两种用例，「最险一口」≥ 3 秒不显示。
- 画面层：慢动作只改喂给 core 的 dt（可用假 match 断言 `update` 收到的 dt），结束后恢复原速；retained 测试覆盖新节点。
- 先红后绿：A、B、C 的关键用例先在没实现时跑一次确认是红的，日志放 `port/tmp/p9-4/`。
