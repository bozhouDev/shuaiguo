## 要做的

### 1. 建工程 `cocos/`

- 仓库根目录下新建 `cocos/`，Cocos Creator 3.8.8、TypeScript、2D 空项目。命令行能建就命令行建；不能的话用编辑器自带的项目模板复制出来，写清楚做法。
- `.gitignore` 忽略 `cocos/library/`、`cocos/temp/`、`cocos/local/`、`cocos/build/`、`cocos/profiles/` 中属于本机的部分（按 Cocos 官方建议）。
- **设计分辨率用 375×812，适配宽度**。这样原型里的所有像素数值（速度、半径、人物高度）能原样搬过来，不用换算。

### 2. 三层目录和启动方式（见计划 §3.1、§3.4）

```
cocos/assets/scripts/
  core/      纯 TS，不 import 'cc'；只用"可擦除"的 TS 语法（不用 enum、namespace、参数属性、装饰器），保证 Node 能直接跑
  view/      Cocos 画面层
  platform/  平台接口：先只定义接口 + 网页实现的空壳 + 微信实现的空壳
  Boot.ts    唯一挂在场景上的组件，所有节点在代码里创建
```

- 场景只有一个：Canvas + 挂 `Boot` 的节点。之后不再新增场景和预制体。
- `core/` 里放一个最小示例（比如 mulberry32 随机数，和原型 `js/engine.js` 的 `E.random` 完全一样的算法），并写一个 Node 测试：同一个种子出的前 1000 个数和原型一模一样（在测试里用 `tests/game-harness.cjs` 加载原型来对比）。
- 测试命令写进 `cocos/package.json` 的 `scripts`（比如 `npm run test:core`），不装依赖能跑最好；必须装的依赖装在 `cocos/` 里，**不要在家目录装**。

### 3. 画面验证（最小内容）

`Boot.ts` 在屏幕上显示：
- 一个像素角色 `player_normal`（来源：`assets/atlas/` 图集 + `js/atlas.js` 位置表，或 `assets/px/player_normal.png`，选你认为后面整批搬素材最顺的方式，说明理由），**最近邻采样，不能糊**，按原型高度 70 显示。
- 一行中文 "这锅你来背"，用站酷快乐体；一行 "背锅 3+1.5"，用思源黑体粗。字体源在 `assets_pixel/fonts_src/`（没有的话看 `assets_pixel/build_fonts.py` 开头的下载地址）。微信加载自定义字体需要 TTF，做一个只含这几个字的 TTF 子集即可验证流程，正式的子集方案在报告里提建议。
- 一个按钮，点一下播放 `assets/audio/ui_click.mp3`，并在控制台打日志。
- 屏幕四角各画一个小色块，用来确认安全区和适配。

### 4. 命令行构建

- 微信小游戏包：命令行构建，AppID 填好，输出在 `cocos/build/wechatgame/`。
- 网页包：命令行构建 `web-mobile`。
- 用微信开发者工具命令行打开构建结果、编译通过；能生成预览二维码就生成到 `port/tmp/preview-qr.png`（`port/tmp/` 不进仓库）。开发者工具要求登录或在设置里开"服务端口"的，停下来报告，写清楚要泊舟做什么。
- 网页包用 `python3 -m http.server` 起来，在浏览器 375×812 打开看一眼，截图。用完关掉服务，确认端口没在监听。
- 每条命令写进 `cocos/package.json` 的 `scripts`（`build:wechat`、`build:web`、`preview:wechat` 之类），以后都用这些命令。

## 裁定（Claude，2026-11-03，回应第一轮"未通过"报告）

**根因已复现：** `library/` 有上一次构建的缓存时，Cocos 命令行模式启动会在 importer 注册完之前扫描 `assets/`，把 `.meta` 的 `importer` 改写成 `"*"`，`ver` 变成 `0.0.1`，场景和资源随之丢失。清掉 `library/`、`temp/`、`build/` 后的第一次构建是好的（Claude 实测：场景、Boot 脚本、角色、两款字体、音效都在产物里）。另外，你的产物检查在压缩后的 `index.js` 里找 `showSmokeView`，名字会被压缩掉，所以那次干净构建也被误判成失败。

按下面继续，把整张任务卡做完：

1. **修好现有 meta**：现在 `cocos/assets/` 下的 meta 已经被写坏（`importer: "*"`）。恢复成正确的 importer 和版本：`Boot.scene.meta` 的 uuid 必须保持 `3b08c73f-d17c-4dfc-a45e-854ddae97b2f`，`Boot.ts.meta` 的 uuid 必须保持不变（场景按 uuid 引用脚本），其余可以删掉让 Cocos 重新生成。
2. **构建脚本 `tools/build.mjs`**：
   - 构建前：确认没有 Cocos 进程在跑这个工程；删除 `library/`、`temp/`、`build/<平台>`；扫描所有 `.meta`，有 `importer: "*"` 就直接失败。
   - 构建后：再扫一次 `.meta`，被改坏就失败并提示；检查产物时只看 `config.json` 里的场景和 `resources` 路径，不在压缩代码里找函数名。脚本是否真的运行，交给网页包的浏览器检查（看控制台日志）。
   - 在脚本注释里写清楚这个坑和处理方法。
3. **稳定性验证**：微信包、网页包各**连续构建 3 次**，每次都通过检查，`git status` 里 meta 没有被改动（先 `git add -N` 或记录哈希来对比，不要提交）。
4. 可选：如果你判断"用编辑器图形界面打开一次工程"能根治这个问题，可以自己用命令行启动编辑器、等它导入完再退出，然后试一次不清缓存的连续构建。不管成没成，都写进报告。但默认方案就是每次清缓存。
5. 然后继续原任务卡没做完的：微信开发者工具命令行打开、编译、预览二维码（要登录或开服务端口就停下报告），网页包浏览器检查和截图，包体报告。
