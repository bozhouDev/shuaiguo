# P7-5 · 性能数据自动上报云数据库 + 渲染分辨率封顶 2 倍 + 大厅动画帧率

先读：`port/tmp/p7-4/report.md`（尤其"渲染分辨率"和"突然变大"两节）、`port/tmp/p7-3/report.md`、`implementation-notes.md` 顶部、`cocos/assets/scripts/view/PerfProbe.ts`、`AppView.ts`（`frameRate` / `frameKey` / 调试面板）、`platform/CloudServices.ts`（`track` 队列）、`platform/WechatPlatform.ts`、`cocos/cloudfunctions/` 全部（尤其埋点函数和它的字段白名单、共享副本检查）、`cocos/build-templates/wechatgame/`、本机 Cocos 3.8.8 的 `pal/screen-adapter/minigame/screen-adapter.ts`。

## 泊舟定的 / 反馈

- 真机（iPhone 17 Pro、小米 17 Pro）第 5 关越到后面越卡，手机发烫。泊舟没找到性能浮层，**要求性能数据自动上报到云数据库**，不用人截图。
- 泊舟说"一打开就感觉分辨率跟以前不一样"。第一轮把静止界面降到 15 帧，大厅里有飘锅、人物走路等动画，可能因此一顿一顿。

## 要做的

### 1. 性能自动上报

- 只在微信开发版 / 体验版开（同 `debugEnabled()` 门禁）；正式版默认关，留一个远程配置开关（走现有调参云配置），以后可以按比例打开。网页不上报。
- 对局中常驻轻量采样（不建浮层节点，不影响画面）：每 30 秒一段，加开局前 10 秒和最后 10 秒，每段记：关卡、段起止秒、场上锅数（取段末）、平均帧间隔、最差 5% 帧间隔、脚本逻辑 / 绘制 ms、draw call、Graphics / Sprite / Label 数、目标帧率、实际渲染倍数（DPR）和画布像素尺寸。
- 每局附一次设备信息：`wx.getDeviceInfo()` 的 brand / model / system / platform，`wx.getDeviceBenchmarkInfo()` 的 benchmarkLevel / modelLevel（接口没有就留空），基础库版本，本局是否开了分辨率封顶。不收集昵称、头像或其他个人信息。
- 一局结束（含被压垮、中途退出、切后台）时把本局记录交给 `CloudServices.track('perf', …)`，走现有队列和批量上传。服务端埋点函数加 `perf` 类型和字段白名单、大小上限，落到 `perf` 集合（自动建，和现有集合一样）。改了云函数要更新共享副本检查和 `test:cloud`。
- 采样本身的开销要量出来写进报告（目标：每帧额外不超过 0.1ms）。

### 2. 渲染分辨率封顶 2 倍

- P7-4 实测：渲染倍数 3→2，帧间隔约降 45%，HUD 文字只略软（`port/tmp/p7-4/dpr-level-5-hud-crop.png`）。现在要在**微信里**真正启用。
- P7-4 已确认 3.8.8 的 `screen.resolutionScale` 不能用。去查微信小游戏下引擎从哪里读像素比（minigame screen-adapter），找一个**不改引擎源码**的办法把渲染倍数封顶到 2：比如在 `build-templates/wechatgame/` 里，在引擎初始化前包一层 `wx.getWindowInfo` / `getSystemInfoSync`，只改 `pixelRatio`，不动 windowWidth / Height / safeArea。逐条说明对触摸坐标、胶囊避让、开放数据域共享画布、分享截图、`toTempFilePath` 的影响，并在 Node 里 mock 测这些换算。
- 默认封顶 2。调试面板加一个"渲染倍数：2 / 原生"切换（存本地，下次启动生效），方便泊舟在同一台手机上对比；上报数据里带上当前倍数。
- 安卓设备像素比可能是 2.x 这种非整数，封顶规则写清楚（建议 `min(原值, 2)`），截图确认像素图不糊。

### 3. 大厅动画帧率

- 大厅有动画（飘锅、人物走路、选关条动效）时保持 60 帧；只有画面完全静止的界面（暂停、稳定后的结算、介绍页）才降到 15 帧。核对大厅、介绍页、结算入场、排行页、toast 期间的帧率，列表写进报告。

## 不能破坏的

- 玩法一帧不变：黄金录像（源码 + `test:golden:compiled`）100/100。
- 画面：除分辨率封顶的预期差异外，固定种子定格截图逐像素比对，方法同 P7-4。
- 门槛同前：core、wechat、cloud、check:types、保护检查、`.meta`、check-spread、perf / tour / result-view 测试全过。

## 不许做的

- 不运行 CocosCreator，不构建，不提交，不推送，不部署云函数（部署要泊舟在开发者工具里右键"上传并部署"，报告里写清楚是哪个函数）。
- 不改原型，不改玩法和数值，不改引擎源码。
