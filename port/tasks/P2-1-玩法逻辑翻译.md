# P2-1 · 玩法逻辑忠实翻译成 TS，黄金录像 100/100 一致

先读：`AGENTS.md`、`port/移植计划.md`（§1、§3、§4 的 P2、§8）、`port/tasks/P0-1-随机种子与黄金录像.md`（含两节裁定）、`tests/golden/record.cjs`、`tests/golden/verify.cjs`、`tests/game-harness.cjs`。然后通读原型 `js/levels.js`、`js/engine.js`（逻辑部分）、`js/game.js`。

## 目标

把原型 `update()` 调用链上的全部玩法逻辑翻译到 `cocos/assets/scripts/core/`，用同样的种子、同样的 dt（1/60）跑，产出的快照和事件日志与 `tests/golden/` 的 100 组录像**逐项完全一致**。

这是"翻译"，不是"重写"。**判断标准只有一个：和原型行为一模一样。** 看到原型里的 bug、怪写法、可以优化的地方，一律照搬，记进报告的"发现但未改"清单，由 Claude 和泊舟另行决定。

## 范围

要翻译（`update()` 能走到的一切）：
- 工具：`E.rand / pick / shuffle / dist / clamp / angDiff`、`E.Snake`（蛇身轨迹）、`E.pushOut / collide`、`Floats`（飘字列表的逻辑部分）等被 update 调用的引擎函数。
- 数据：`js/levels.js` 的 `OFFICE`、`LEVELS` 原样搬成 TS 数据（数值、顺序、字段名都不变）。
- `js/game.js`：常量、`PERSONAS`、`LEADER_TYPES`、`EVENTS`、`INCIDENT_MSGS`、`BUFFS`；对局状态构造（`makeState`、`makeAgent`、`makeLeader`、`buildSchedule`）；锅、飞行、甩锅、反甩、到期爆炸、背锅；寻路；领导（巡逻、瞄准、视野、抓现行、追人、发火、查岗、画饼会议）；同事 AI（`think`、`updateAgent` 等）；小舅子、老板娘、出纳；日程和随机事件；急着下班；带教（`updateTutorial` 等，录像不覆盖，但照样翻译，P2-2 补测试）；`ranking`；收尾计时里属于逻辑的部分。
- 原型里 update 调用链上调用的 `showHint`、`showMsg`、`E.toast`、`E.sfx`、`E.buzz`、`praise`、`spawnFx`、`floats.add`、`shake` 等表现调用：**在 core 里变成事件**（见下）。

不翻译：`draw*`、HUD/DOM、大厅、介绍页、结算界面、分享、设置、音频实现。`finish()` 里算名次、星级、总账、复盘推荐的**纯计算部分**要翻译成 core 的函数（P2-2 测），界面部分不管。

## 结构要求

- **只用可擦除的 TS 语法**（不用 enum、namespace、参数属性、装饰器），不 `import 'cc'`，Node 23 `--experimental-strip-types` 能直接跑。
- **不用全局状态。** 原型的闭包变量（`S`、`L`、`mode`、`auto`、`simulating`、`shake` 等）收进一个对局对象（比如 `Match`），一个进程里能同时开多局。随机数由对局持有（`core/random.ts` 的 `Mulberry32`），**调用顺序必须和原型一致**。
- **字段名保持原型的写法**（`a.sn.segs`、`S.t0`、`l.throwCd` 等），这样快照映射几乎是一一对应，翻译也最不容易错。可读性以后再改。
- **表现事件出口**：core 定义一个事件接口（比如 `onEvent(kind, ...args)` 或一组回调），原型里每一处表现调用都变成一次事件，**参数和调用时机与原型一致**（录像的事件日志就是这些调用的记录）。表扬贴纸按 P0-1 裁定不进录像，但 `praise(kind)` 的调用意图也要作为事件发出，留给画面层。
- 模块怎么拆你定，单文件不要超过约 800 行；每个文件开头写一句它对应原型的哪些函数。
- 所有函数和关键逻辑写中文注释（照搬原型注释即可，原型注释已经很全）。
- 涉及 `Array.prototype.sort`、对象遍历、`Set` 迭代的地方，保持和原型相同的数据结构和插入顺序。

## 黄金录像接入

- 写 `cocos/tests/golden-adapter.*`：导出 `runCase(level, seed)`，用 TS core 跑一局，返回和 `tests/golden/record.cjs` 的 `runCase` **完全同结构**的结果（快照字段、事件日志格式、`result`）。快照的取数规则照 `record.cjs` 的 `snapshot()` 来。
- `tests/golden/verify.cjs` 已支持 `--adapter`。如果它只能 `require` CJS 而你的适配器是 ESM，可以**只为加载方式**改 `verify.cjs`（比如改用动态 `import()`），比对逻辑一行都不许动。
- 在 `cocos/package.json` 加 `test:golden` 命令。

## 验收门槛

1. `node tests/golden/verify.cjs --adapter <你的适配器>`：**PASS 100/100**。
2. 原型自身 `node tests/golden/verify.cjs` 仍然 100/100（证明你没动原型和录像）。
3. `npm run test:core --prefix cocos`、`npm run check:types --prefix cocos` 通过。
4. 原型文件（`js/`、`index.html`、`css/`、`assets/`、`tests/golden/*.gz`、`manifest.json`）哈希不变。

调试方法：verify 会报第一个不一致的关卡、种子、时间、字段。先让关卡 0 种子 1001 通过，再逐步扩大。**不许为了通过而改录像、放宽比对、或在适配器里"修正"数值**——不一致只能通过把翻译改对来解决。如果确信是录像本身有问题（比如录像依赖了 harness 的桩），停下来报告证据。

## 不许做的

- 不改原型代码和录像。
- 不碰 `cocos/assets/scripts/view/`、`platform/`、场景和素材（Cocos 编辑器正开着这个工程，**不许运行 `CocosCreator`，不许启动 Cocos 进程**；只改 `core/` 和测试不会触发问题，新增的 `.ts` 文件会被编辑器自动生成 `.meta`，这是正常的，一并留着）。
- 不"顺手改好"任何东西。
- 不提交、不推送、不部署。
- 遇到计划外情况，选保守做法并停下来报告。
